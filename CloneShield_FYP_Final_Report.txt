FINAL YEAR PROJECT REPORT
Project Title: CloneShield - An Adversarial Defense System Against Malicious Voice Cloning
====================================================================

CHAPTER 1: INTRODUCTION AND BACKGROUND
--------------------------------------------------------------------
1.1 Motivation
In recent years, the advancement of Generative Artificial Intelligence and deep learning has revolutionized Text-To-Speech (TTS) synthesis. State-of-the-art zero-shot TTS models, such as XTTSv2, possess the capability to accurately mimic the timbre, prosody, and emotional cadence of a specific speaker using as little as a 3-second audio sample. While this technology has legitimate applications in accessibility and entertainment, it has simultaneously introduced severe cybersecurity and ethical risks. Malicious actors routinely utilize voice cloning for deepfakes, sophisticated phishing attacks (vishing), biometric authentication circumvention, and identity theft.

1.2 Problem Statement
Current digital audio platforms lack intrinsic protection mechanisms against voice data harvesting. Once an individual's voice is uploaded to the internet—be it through a podcast, video, or social media—it is permanently vulnerable to being scraped and fed into an unauthorized TTS encoder. 

1.3 Proposed Solution
This project introduces "CloneShield", an end-to-end adversarial defense architecture. CloneShield acts as a proactive security layer that injects mathematically constrained, imperceptible adversarial noise into audio files. This noise functions as a "cryptographic poison" that exploits the underlying vulnerabilities in the feature extraction latent space of TTS models. While a human listener perceives the protected audio as clean and understandable, the TTS encoder perceives a chaotic distortion, ultimately causing the voice cloning process to fail or hallucinate.

CHAPTER 2: PROPOSED METHODOLOGY AND NEURAL ARCHITECTURE
--------------------------------------------------------------------
CloneShield employs a dual-stage neural pipeline, meticulously balancing aggressive adversarial disruption against strict perceptual fidelity constraints.

2.1 Stage 1: The Perturbation Generator (1D U-Net)
The primary mechanism of the system is the Perturbation Generator, modeled as a 1D Convolutional U-Net. 
- Input: The network accepts a raw, one-dimensional audio waveform.
- Bottleneck: The input is downsampled through a series of convolutional layers to extract temporal and spectral features, then upsampled back to the original resolution.
- Output: The network produces a targeted adversarial noise pattern specifically designed to disrupt Mel-spectrogram extraction.
- The Epsilon Constraint: To guarantee the noise does not ruin the audio for human listeners, the generator's output is bounded by a strict "Epsilon" budget (e.g., max amplitude deviation <= 0.05). The output tensor undergoes a clamping operation relative to the maximum amplitude of the original waveform, structurally preventing speaker blowout or heavy clipping.

2.2 Stage 2: FilterNet (Intelligent Noise Pruning)
Raw adversarial noise often contains high-frequency "hiss" or broad-spectrum static that degrades the listening experience. To solve this, a secondary network named "FilterNet" was developed.
- FilterNet analyzes the raw adversarial noise generated by the U-Net and maps it against the original waveform.
- It outputs a non-linear Sigmoid mask (ranging from 0.0 to 1.0) representing the "necessity" of the noise at any given microsecond.
- A user-controlled parameter, `filter_strength`, allows the system to scale this mask. FilterNet successfully prunes away mathematically redundant static, maximizing the perceptual quality of the audio while preserving the core adversarial attack vectors.

CHAPTER 3: TRAINING DYNAMICS AND VULNERABILITY MITIGATION
--------------------------------------------------------------------
3.1 Differentiable Mel-Spectrogram Loss (Mel-Loss)
Traditional adversarial attacks (like FGSM or PGD) target image classifiers. Audio TTS models are fundamentally different because they convert raw waveforms into Mel-spectrograms before extracting speaker embeddings. CloneShield utilizes a custom, differentiable Mel-Loss function. During training, the system calculates the Mean Squared Error (MSE) between the Mel-spectrogram of the clean audio and the protected audio. The optimizer's objective is to completely maximize this distance in the latent space, effectively blinding the TTS encoder.

3.2 The Receptive Field Patch (Averaging Vulnerability)
During early testing, a critical architectural vulnerability was discovered in how modern TTS systems process audio. Models like XTTSv2 break audio into tiny consecutive windows and calculate the "average" latent vector across time. If adversarial noise is completely uniform, the TTS encoder averages the noise out to zero, effectively bypassing the protection entirely.
- The Fix: The training methodology was re-engineered to simulate dynamic windowed processing. By chunking the training audio into discrete 6-second segments, the U-Net learned to generate aggressive, non-uniform perturbations that actively disrupt the averaging mechanism itself. This breakthrough ensured robust defense against real-world XTTS inference.

CHAPTER 4: DEPLOYMENT ARCHITECTURE
--------------------------------------------------------------------
To prove real-world viability, CloneShield was deployed using a distributed Edge-to-Cloud architecture, bridging a mobile application with a GPU-accelerated backend.

4.1 The Fakeless Cloud API (Render)
The primary API is hosted on Render using the FastAPI framework. Operating within a heavily constrained 512MB RAM environment necessitated extreme optimization:
- Dependency Scrubbing: Heavy scientific analytical libraries (such as SciPy and PyStoi) were actively stripped from the environment. Retaining them caused Out-Of-Memory (OOM) timeouts during the 60-second Render boot sequence.
- Codec Isolation: PyTorch's native Torchaudio FFmpeg backend was bypassed entirely to prevent Linux container crashes. The native `soundfile` library handles binary deserialization directly into NumPy matrices.
- Serialization: The API utilizes a structured JSON protocol. Protected audio is converted into a continuous Base64 string payload, allowing the Flutter mobile app to seamlessly parse and natively decode the audio without relying on raw binary HTTP file transfers.

4.2 The Attacker Proxy (XTTS Bridging)
To scientifically demonstrate the protection in real-time, the Cloud API integrates a secure `/clone` proxy route. The proxy connects the Render cloud server to a local, GPU-accelerated Desktop environment via an Ngrok tunnel. The Desktop PC houses the massive XTTSv2 parameters, executes the unauthorized voice clone, and streams the failed cloning attempt back through the cloud directly to the user's mobile device.

CHAPTER 5: EVALUATION METRICS AND RESULTS
--------------------------------------------------------------------
The system's efficacy is continuously verified using three strict metrics dynamically calculated in the backend:

1. SNR (Signal-To-Noise Ratio): Calculated natively using instantaneous PyTorch tensor mathematics. It measures the decibel (dB) ratio between the clean audio signal and the adversarial noise. Lower SNR indicates robust protection at the cost of static, while a higher SNR indicates pristine audio with a lighter adversarial footprint.
2. Max Perturbation Constraint: The system algorithmically verifies that the highest point of noise generated by the U-Net strictly obeys the Epsilon limitation, proving mathematical stability.
3. PESQ (Perceptual Evaluation of Speech Quality): An industry-standard ITU-T algorithm used to grade subjective human-listening quality. The integration of FilterNet drastically increased overall PESQ scores while maintaining TTS disruption.

CHAPTER 6: CONCLUSION
--------------------------------------------------------------------
The CloneShield project successfully proves that zero-shot voice cloning architectures can be systematically defeated. By engineering a dual-stage adversarial U-Net paired with an intelligent FilterNet, the system successfully poisons the latent embedding space of XTTS models without severely degrading the underlying audio file for human listeners. The lightweight Cloud API optimization and seamless Base64 JSON integration demonstrate that CloneShield is a highly scalable, real-world defensive tool capable of combating the imminent threat of deepfake voice synthesis.
